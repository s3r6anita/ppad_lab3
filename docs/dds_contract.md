# Контракт DDS

## Назначение

DDS хранит типизированные состояния репозиториев и issues/PR,
наблюдавшиеся в успешных батчах STG.

Локальная база разработки: ppad_dds_dev.
Схема: dds.

STG используется только для чтения.
CDM и дашборды не входят в этот этап.

## Таблицы

### dds.repositories_scd2

Одна строка — одна наблюдавшаяся версия репозитория.

Натуральный ключ: github_repository_id из payload.id.
Суррогатный ключ версии: repository_version_id.

Бизнес-поля:
- full_name
- description
- language
- stars_count
- forks_count
- open_issues_count
- archived
- source_created_at

Счетчики включены в историю намеренно:
для первой версии требуется сохранять изменения этих показателей.

### dds.issues_scd2

Одна строка — одна наблюдавшаяся версия issue или PR.

Натуральный ключ: github_issue_id.
Суррогатный ключ версии: issue_version_id.

Бизнес-поля:
- github_repository_id
- issue_number
- title
- state
- is_pull_request
- author_id
- author_login
- source_created_at
- source_closed_at
- labels
- assignees

github_repository_id определяется через запись репозитория
из того же батча и с тем же repository_full_name.

issue_number не является глобальным идентификатором.

Автор хранится атрибутами версии issue.
Отдельная история пользователей в первой версии не ведется.

labels — JSON-массив объектов с полями id и name.
assignees — JSON-массив объектов с полями id и login.
Массивы нормализуются по id; порядок элементов
в исходном JSON не считается изменением.

Описание issue (body), URL и прочие не перечисленные
поля в первую версию DDS не переносятся.
Исходный JSON остается доступен в STG.

### dds.processed_batches

Одна строка — один успешно обработанный батч STG.

Ключ: batch_id.

Хранятся:
- время начала батча STG
- время завершения обработки в DDS
- количества прочитанных репозиториев и issues/PR
- количества созданных версий репозиториев и issues/PR
- количества закрытых версий репозиториев и issues/PR

Отметка обработки сохраняется в той же транзакции,
что и изменения исторических таблиц.

## Общие поля исторических таблиц

- Суррогатный ключ версии: bigint identity.
- Натуральный ключ GitHub: bigint.
- valid_from: timestamptz.
- valid_to: timestamptz, NULL для текущей версии.
- is_current: boolean.
- hash_diff: хеш нормализованных бизнес-полей.
- source_batch_id: батч, создавший версию.
- source_updated_at: время updated_at из исходного JSON.
- dds_loaded_at: техническое время создания версии в DDS.

source_updated_at сохраняется как метаданные версии,
но не входит в hash_diff.
Оно не обновляется у неизменной версии при каждом батче.
Последнее наблюдение объекта определяется по STG.

batch_id, source_updated_at, loaded_at, source_url
и технические поля DDS не входят в hash_diff.

## Временная семантика

valid_from новой версии равен started_at исходного батча STG.

При изменении:
- valid_to предыдущей версии = started_at нового батча;
- valid_from новой версии = started_at нового батча.

Интервал версии: [valid_from, valid_to).
Для текущей версии valid_to IS NULL.

Это время наблюдения в рамках батча, а не точное время
изменения объекта в GitHub.
Сбор страниц не является атомарным снимком.

Если новая версия потребовала бы нулевого или отрицательного
интервала, загрузка завершается ошибкой.
Автоматически сдвигать временные границы нельзя.

## Алгоритм обработки

1. Получить блокировку, исключающую параллельную загрузку DDS.
2. Выбрать успешные батчи STG, отсутствующие в processed_batches.
3. Обрабатывать их в порядке started_at, batch_id.
4. Для каждого батча проверить полноту и согласованность STG.
5. Преобразовать JSON в типизированные бизнес-поля.
6. Загрузить версии репозиториев.
7. Загрузить версии issues/PR.
8. Записать processed_batches.
9. Зафиксировать транзакцию одного батча.

Новая сущность: вставить текущую версию.
Неизменная сущность: не изменять историческую таблицу.
Измененная сущность: закрыть текущую версию и вставить новую.

Отсутствие объекта в следующем батче
не считается доказательством удаления.

Если обнаружен ранее не обработанный батч, который предшествует
уже обработанному в порядке started_at, batch_id,
загрузка останавливается: требуется отдельная процедура
перестроения истории, а не вставка задним числом.

## Ограничения и проверки

- Не более одной текущей версии на натуральный ключ.
- is_current согласован с valid_to IS NULL.
- У закрытой версии valid_to > valid_from.
- Интервалы одного натурального ключа не пересекаются.
- У issue существует репозиторий с соответствующим GitHub ID.
- Повтор обработанного батча не изменяет DDS.
- Второй неизменный снимок не создает новых версий.
- Ошибка внутри батча откатывает его изменения целиком.

Связь issue с репозиторием хранится по стабильному GitHub ID.
Она не закрепляет issue навсегда за конкретной
SCD2-версией репозитория.

При историческом соединении версий необходимо учитывать
интервалы обеих таблиц.

## Проверенные и будущие тесты

Проверены:
- первичная загрузка двух переданных батчей;
- повтор загрузчика без изменения содержимого DDS;
- контролируемое изменение бизнес-полей репозитория и issue;
- нормализация labels/assignees, включая независимость
  хеша от порядка элементов — модульными тестами;
- полный откат изменений батча при искусственной ошибке;
- успешная повторная обработка после устранения ошибки;
- непрерывность границ версий в тестовой истории;
- отказ второго загрузчика при занятой advisory-блокировке.

Дополнительно планируются отрицательные проверки:
- попытка вставки пересекающихся интервалов;
- попытка создания двух текущих версий одной сущности;
- обработка запоздавшего батча;
- изменение сущности в батче с тем же started_at.

Тестовые изменения не вносятся в исходный переданный STG.
Для них используется отдельная тестовая база.

Команды и результаты проверок описаны в docs/dds_runbook.md.

## Интеграция

Для общей демонстрации те же миграции и загрузчик
применяются к рабочей базе ppad_dwh.

Подключение к базе передается настройками:
имя ppad_dds_dev не зашивается в бизнес-логику.

Сервисная учетная запись загрузчика DDS должна иметь
чтение STG и необходимые права записи DDS.
ppad_loader первого участника для этого не используется.

## Физическая реализация первой версии

Для запрета пересечения интервалов используется расширение btree_gist
и EXCLUDE-ограничения по натуральному ключу и tstzrange.

hash_diff хранится как SHA-256 в шестнадцатеричном формате.

author_id и author_login допускают NULL.

Связь issues_scd2.github_repository_id с репозиторием
проверяется загрузчиком в транзакции и контрольным запросом.
Обычный внешний ключ на историческую таблицу не создается,
поскольку GitHub ID повторяется в разных версиях.
Прямые записи в DDS в обход загрузчика эту связь не гарантируют.

Наличие и порядок объектов внутри labels и assignees
проверяются и нормализуются загрузчиком.
DDL проверяет только то, что эти поля являются JSON-массивами.
